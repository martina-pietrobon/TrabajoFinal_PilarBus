# TrabajoFinal_PilarBus
Prototipo de la aplicación PilarBus.

Se utilizarán Pull Requests para que cada integrante pueda compartir los cambios que realizó y que el resto del equipo pueda revisarlos antes de agregarlos a la rama principal. También se implementará CI/CD, un proceso que permite comprobar automáticamente que los cambios no tengan errores antes de publicar una nueva versión de la aplicación. Para ello, se realizarán dos comprobaciones:
- Build: verifica que el proyecto esté preparado correctamente y no tenga errores.
- Test: comprueba que las funciones de la aplicación trabajen como deberían.
De esta manera, se busca evitar errores y asegurarse de que la aplicación funcione correctamente antes de cada publicación.

En pocas palabras, los Pull Requests sirven para revisar los cambios del equipo, mientras que CI/CD ayuda a comprobar automáticamente que esos cambios funcionen antes de publicar una nueva versión de la aplicación.
